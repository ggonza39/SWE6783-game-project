# Pixel Rebellion: Shadow Protocol – Control Mapping

This document defines the planned player controls and the UX purpose of each input. The control scheme is intentionally kept familiar and consistent so that first-time players can begin playing without having to memorize a large number of commands.

| Action | Control | UX Purpose |
|---|---|---|
| Move Up | W / Up Arrow | Familiar directional movement |
| Move Left | A / Left Arrow | Familiar directional movement |
| Move Down | S / Down Arrow | Familiar directional movement |
| Move Right | D / Right Arrow | Familiar directional movement |
| Sprint | Left Shift | Allows faster movement when needed |
| Interact | E | Used for evidence, terminals, and other interactable objectives |
| Restart | R | Provides a quick way to recover after failure |
| Pause / Help | Esc | Gives access to pause and control information |
| Menu Selection | Mouse | Used for menus and other interface selections |

## UX Notes

- Movement should respond immediately when the player presses a movement key.
- WASD and Arrow Keys support the same movement actions so players can use the layout they are most comfortable with.
- The same interaction key should be used consistently for relevant objects to reduce confusion.
- Important interactions should provide immediate visual feedback so the player knows the input was registered.
- Control instructions should be shown during the briefing/tutorial and remain accessible from the Pause / Help screen.
